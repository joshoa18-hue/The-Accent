# Working on The Ascent

Guidance for AI coding assistants (and humans) working in this repository. `AGENTS.md`, imported above, is generated by Next.js. Obey it: **this is Next.js 16**, so read `node_modules/next/dist/docs/` before using an API you're unsure of.

## The owner is learning

The project owner is learning web development through this project. For every substantial change:

- Plan first and wait for approval.
- Explain **what** was built, **why**, the important files and code, how the pieces communicate, the concepts to study, and give a short exercise. Lessons live in `docs/learning/`.

## Non-negotiable rules

1. **No fake functional buttons.** If it looks clickable, it must work. Display-only UI must look display-only. Tests enforce this for missions and courses.
2. **Never award or change XP from the browser.** XP is a ledger (`xp_transactions`). It's written only by trusted server code (the `award_xp` database function, Milestone 3). Never add a data-layer function that writes XP from client state.
3. **No secrets in the repo.** Only `.env.example`, with placeholders, is committed. Service-role keys never reach client code; modules that use them import `server-only`.
4. **No unnecessary dependencies.** Ask before adding one, and prefer the platform: native HTML, CSS and Next.js built-ins.
5. **No destructive operations without approval** (deleting data or files, force-pushing, rewriting history, dropping tables).
6. **Don't claim something works unless it has been tested.** Run `npm run check`, and check UI changes in a browser.
7. **Label sample data.** Anything not from the database goes through `src/content/sample/` and shows `SampleDataNotice`.

## Architecture in one minute

- `src/app/`: routes. These are Server Components that load data in parallel and compose sections.
- `src/lib/data/`: the **only** place that knows where data comes from. It returns `DataResult<T>` = `{ data, source }`.
- `src/lib/progression/`: pure game rules (levels, ledger, attributes). Keep them pure and tested.
- `src/components/`: display only. Props in, UI out. `"use client"` only when the browser is truly required.
- `src/lib/routes.ts`: build every internal URL here.
- Anything reading `params` or `usePathname` must be inside `<Suspense>` (Cache Components). See ARCHITECTURE.md §6.

Full details are in [ARCHITECTURE.md](ARCHITECTURE.md), the plan in [ROADMAP.md](ROADMAP.md), and the database in [docs/DATABASE_DESIGN.md](docs/DATABASE_DESIGN.md).

## Commands

```bash
npm run dev          # http://localhost:3000
npm run check        # lint + typecheck + tests + build; must pass before committing
npm run test:watch   # tests while you work
```

## Conventions

- TypeScript strict. No `any`. Prefer `Record<Union, …>` lookup tables so new union members are caught by the compiler.
- Tests sit next to the code (`*.test.ts(x)`). Component tests start with `// @vitest-environment jsdom` and query by role and text.
- Tailwind tokens come from `globals.css` `@theme`. Use them rather than raw hex values in components.
- Accessibility: real headings, `<section aria-labelledby>`, status shown in words and not only colour, and keyboard access for everything.
- Commits: one logical change each, and `npm run check` green.
